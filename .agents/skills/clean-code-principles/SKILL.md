# Clean Code Principles

When writing or refactoring code, you MUST adhere to the following principles:

1. **Naming Conventions**: Use intention-revealing names. Variables should be nouns, functions should be verbs. Avoid abbreviations.
2. **KISS (Keep It Simple, Stupid)**: Favor readability and simplicity over cleverness.
3. **DRY (Don't Repeat Yourself)**: Extract duplicated logic into reusable functions or constants.
4. **YAGNI (You Aren't Gonna Need It)**: Do not add functionality until it is actually needed.
5. **Functions**: Keep functions small. A function should do exactly ONE thing (Single Responsibility).
6. **Comments**: Code should explain *what* it does. Comments should only explain *why* (context/business logic).
7. **SOLID**: 
   - Single Responsibility Principle
   - Open/Closed Principle
   - Liskov Substitution
   - Interface Segregation
   - Dependency Inversion
